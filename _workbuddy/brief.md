# 图鉴文案重写任务 · brief

你是文案作者。任务：把下面这些僵尸的**图鉴文本**重写一遍，风格用「宝开语」。

只写文案。**不要碰任何数值、不要改 codename、不要新增机制描述。**

## 一、什么是「宝开语」

PopCap / 宝开官方中文图鉴的腔调。它的骨架是**先正经陈述，再冷不丁拆台**：

- 开头像一份官方档案：平铺直叙地说明它是什么、干什么。
- 中段给一个具体到有点多余的细节（数字、时间、某人的坚持）。
- 结尾抖一句冷幽默，通常是把前面的话自己拆掉，或者借「他本人表示 / 工作人员称 / 据说」把责任推出去。

三个真例子（照这个味道写，不要照抄句子）：

> 国王僵尸一直认为自己是个慷慨的君主。他确实很慷慨——每册封一位骑士，他都会从自己身上慷慨地划走 150 点血。

> 弄臣僵尸的旋转是一门艺术。艺术不能当饭吃，转久了还会头晕。据他本人说，头晕是因为观众不懂欣赏。

> 重金属巨尸在舞台上从不失手。他现在也不失手了，因为他已经不弹了。

**要**：短句、具体、克制、自嘲、把玩家会遇到的坑写成段子。
**不要**：网络流行语（yyds、破防、栓 Q 这类）、感叹号连用、抒情、说教、形容词堆砌、玩梗玩到看不懂。

## 二、字段规则

每条要产出三块：

1. `intro`（图鉴「介绍」，一到两句）
   说明它是谁、在场上干什么。改动过行为的地方要在这里就体现。
2. `special`（图鉴「特点」，数组，每条一句话）
   - 保留原作里仍然成立的技术描述（可以改写得更顺）
   - **新增一条**专门讲这次改动，`name` 统一写 `{"en":"Special","zh":"特点"}`
   - 数组整体替换，所以要把该僵尸该有的条目都写全
3. `chat`（图鉴底部那段「闲聊」，100~200 字）
   这是宝开语的主战场。写它的性格、怪癖、和改动有关的小故事。

`intro` / `chat` 都是 `{"en": "...", "zh": "..."}` 双语，英文同样要用 PopCap 英文图鉴的腔调（dry、自嘲、拟官方），不是直译。

## 三、输出格式（严格）

一个 JSON 文件，UTF-8，结构如下，**不要加注释、不要加 markdown 代码围栏**：

```json
{
  "zombies": [
    {
      "codename": "被指定的 codename",
      "intro": { "en": "...", "zh": "..." },
      "special": [
        { "name": { "en": "Special", "zh": "特点" }, "desc": { "en": "...", "zh": "..." } }
      ],
      "chat": { "en": "...", "zh": "..." }
    }
  ]
}
```

`bosses` 批次的条目多两个字段 `name`（新名字，双语）与 `title`（可选，一句话称号）。

**必须**：每个 codename 都要出现；special 至少一条；JSON 必须能被 `JSON.parse` 解析。
